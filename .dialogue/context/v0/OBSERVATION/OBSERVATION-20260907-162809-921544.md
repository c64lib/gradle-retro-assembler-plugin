Observation: DASM assembler support already exists on develop (PR #131, commit 6215b0e, feature #129). Implemented as compilers/dasm hexagonal module (DasmAssembleUseCase, DasmAssemblePort, DasmAssembleAdapter via project.exec against PATH-installed dasm binary) plus flows integration (DasmStep, DasmStepBuilder, dasmStep {} DSL, DasmAssembleTask, wired in RetroAssemblerPlugin.wireFlows). Documented in user manual doc/index.adoc section 'dasm Step' and arc42 docs. Gaps: (1) not in any release - latest tag 1.8.0 predates it; (2) zero unit tests for any DASM class; (3) not selectable via legacy retroProject dialect enum (AssemblerType deprecated, never branched on anyway); (4) no binary download/version management - PATH-only, unlike KickAssembler jar auto-download; (5) 64spec test pipeline remains KickAssembler-only. Recorded design decision on file (.ai/129-dasm-support, arc42): DASM is flows-only and PATH-based by design.
